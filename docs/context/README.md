# docs/context — то, к чему возвращаемся каждую сессию

Папка для долгоживущего контекста фронтенд-разработчика. Всё, что нужно
перечитать в начале сессии или при спорном решении, лежит здесь; рабочие
файлы (план, решения, заглушки) остаются в корне `docs/`.

## Порядок чтения в начале сессии

1. `docs/frontend-plan.md` — где остановились и что берём.
2. `docs/decisions.md` — почему сделано именно так.
3. `docs/stubs.md` — какие заглушки ещё активны.
4. Эта папка — только когда нужен контракт, состав досье или сверка с ТЗ.

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `sources-of-truth.md` | Какой документ главнее какого и что в старом ТЗ устарело |
| `2026-08-04-updated-spec.md` | Разбор обновлённого ТЗ: что закрыто, что изменилось, что новое |
| `frontend-api-contract.md` | Контракт фронт↔бэк одной страницей: эндпоинты, null-правила, замороженные решения |
| `frontend-role-checklist.md` | Этапы F0–F9 из плана роли с отметками нашего фактического состояния |

## Правила папки

- Сюда попадает только то, к чему реально возвращаются. Черновики и разовые
  заметки — не сюда.
- Каждый файл начинается с даты и источника: чей документ, от какого числа.
- Если факт устарел — правим файл, а не дописываем «на самом деле уже нет»
  в конец. Исключение — таблицы истории изменений контракта.
