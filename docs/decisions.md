# Принятые решения

Формат: решение — одна строка обоснования. Даты по сессиям.

## Сессия 1 (04.08.2026, аудит)

- **shadcn/ui (Base UI) + Tailwind вместо CSS Modules из ТЗ §11** — осознанный отход:
  копируемые компоненты, а не тяжёлая библиотека; на 60-часовом сроке экономит время.
- **Линейная SVG-схема реки вместо карты** — ТЗ §17 запрещает приблизительные координаты,
  §18 признаёт схему достаточной; MapLibre только после подтверждённых координат и при
  запасе времени (офлайн-тайлы — отдельный риск, демо без интернета).
- **Заглушки только в `src/api/`** с сигнатурами реальных эндпоинтов — замена на бэк =
  правка одного файла; компоненты не трогаются. Значения — только реальные из ТЗ §5.
- **Печатное досье делает фронт** из тех же данных, что экран; бэковский
  `GET /api/investigations/:id/export` не используем. (Дефолт — ждёт подтверждения
  команды, вопрос 5 в плане.)
- **react-router-dom одобрен** — нужен для `/dossier/:id` и deep-links; самодельный
  hash-роутинг — ложная экономия.
- **.env-политика:** во фронте секретов не бывает (всё `VITE_*` запекается в бандл);
  в git — только `.env.example` с `VITE_API_BASE_URL`; `.env` добавить в `.gitignore`
  (сейчас игнорируется только `*.local`); чтение с фолбэком — сборка работает без `.env`.
  Настоящие секреты (ключи Gemini/Groq) — только на бэке, вопрос 13 в плане.
- **Станции с `riverOrder = null` не встраиваются в линию схемы** — отдельная группа
  «порядок не подтверждён»: ТЗ запрещает тихое ранжирование без подтверждённого порядка.
- **Выбор расследования и месяца хранится в URL** — deep-link для защиты, устойчивость к F5.
- **Цвет значений** — предложена монохромная min–max нормировка внутри события;
  НЕ РЕШЕНО, ждёт команду (вопрос 10). Самодельную шкалу «опасности» не вводим.
- **Монорепа по ТЗ §11 принята и выполнена в сессии 1** — бэкендеры работают
  коллабораторами в этом же репо, поэтому структура (`apps/web` + npm workspaces
  в корне) зафиксирована до их первого коммита; переезд после 30-го часа стоил бы
  конфликтов во всех ветках. Lock-файл теперь один, корневой.
- **`__dirname` → `import.meta.dirname` в vite.config.ts** — Vite 8 предупреждает
  о несовместимости с будущим `configLoader: 'native'`; Node ≥ 20.19 это поддерживает.

## Сессия 2 (04.08.2026, типы + константы + api-слой)

- **Провизорные формы ответов API вынесены в `src/api/contracts.ts`, а не в `src/types/`** —
  вопросы 2/3/6 открыты, но ждать нельзя; типы ТЗ §8 остаются нетронутыми, при ответе
  команды правятся только `contracts.ts` и `seed-data.ts`, компоненты не трогаются.
- **`riverOrder` во всех заглушках = null** — ТЗ §8 разрешает его только после ручной
  проверки порядка (вопрос 1); пары «выше/ниже» из подписей створов закодированы честно
  через `relationType` + `relatedObjectId`.
- **Коридор в заглушках — `corridorBounds` парой stationId, `corridor` (GeoJSON) = null** —
  координаты не подтверждены (ТЗ §17), для линейной схемы нужны именно границы-створы;
  `upstreamStationId: null` кодирует открытый вверх интервал («выше створа X», сентябрь).
- **Payload реплея — провизорный дискриминированный юнион `TypedReplayStep`** в contracts.ts
  (вопрос 3); в `src/types/replay.ts` payload остаётся `unknown` — 1:1 с ТЗ §12.
- **@types/geojson поставлен dev-зависимостью** — `Investigation.corridor` в §8 типизирован
  как `GeoJSON.Feature`; пакет только с типами, не «тяжёлая зависимость».
- **Неизвестное не выдумывается, а кодируется явно:** `publishedAt: null`, `sha256: ''`
  (посчитает бэк), майская `sourcePage: 0` до перепроверки (вопрос 8), `sampledAt`
  с точностью до месяца (`'2025-09'`) — точных дат отбора в ТЗ нет.
- **Кейс Актау — минимальный investigation L0 без выдуманных сигналов** (вопрос 7 открыт):
  unknowns и вывод — дословно по ТЗ §7.6/§13.
- **react-refresh/only-export-components отключён для `src/components/ui`** — shadcn штатно
  экспортирует `buttonVariants` рядом с компонентом; правило мешает только сгенерированным файлам.
- **Уровни сентябрь L2 / май L3 — из ТЗ §14**, фронт их не вычислял и не будет (запрет 6).

## Сессия 3 (04.08.2026, каркас трёх колонок + шкала)

- **Хром интерфейса — ахроматический; цвет несут только уровни доказательности §6
  и данные** — прямое следствие запрета 4 (никаких шкал «опасности»): когда сам
  интерфейс бесцветен, янтарный/зелёный статус читается как смысл, а не как декор.
- **Порядок и нумерация блоков правой панели живут в `CONCLUSION_SECTIONS`
  (`src/constants/panel.ts`)** — §13 сам нумерует блоки 1–6, панель рендерит массив
  как есть; поменять порядок можно только в одном месте, и это будет видимое решение.
- **Маркеры шкалы реплея стоят на реальных `offsetMs` (§12), а не равномерно** —
  шкала это хронология доказательств, а не прогресс-бар; порядок типов шагов
  зафиксирован в `REPLAY_STEP_TYPE_ORDER` по сценарию §14.
- **QueryClient: `staleTime: Infinity`, `retry: false`, `refetchOnWindowFocus: false`** —
  демо офлайн с проектора, данные месячных бюллетеней не меняются во время показа;
  live-status при подключении задаст свои опции на уровне запроса.
- **В сгенерированном shadcn `scroll-area.tsx` удалён неиспользуемый импорт React** —
  `tsc -b` с noUnusedLocals валит сборку; это правка сгенерированного файла, при
  повторной генерации компонента её нужно повторить.
- **Мобильная вёрстка каркаса — просто складывание колонок в столбец на `<lg`** —
  по плану мобильность остаточным принципом (блок 45–52 ч), но каркас не ломается.

## Сессия 4 (04.08.2026, common-примитивы + lib/format)

- **Палитра §6 — только в `EvidenceLevelBadge` (TONE_CLASSES)** — `constants/evidence.ts`
  хранит абстрактный `tone`, конкретные css-классы в одном компоненте: перекрасить
  уровни можно в одном месте, и никто не растащит цвета по экранам.
- **Числа: максимум 3 знака, хвостовые нули не дорисовываются** — экран показывает
  число 1:1 как в таблице бюллетеня §5 (0,234); дорисованный нуль был бы «выдуманной»
  точностью. Между числом и единицей — ` ` (неразрывный пробел, явный escape,
  не литерал — литерал неотличим от пробела в diff).
- **Даты — фиксированная зона `Asia/Atyrau`, не зона браузера** — весь Казахстан
  с марта 2024 в едином UTC+5 без сезонных переводов; демо показывает одни и те же
  часы на любой машине. Зона — модульная константа `lib/format.ts`, в JSX не попадает.
- **`formatSampledAt` честен к точности данных** — `'2025-09'` рендерится
  «сентябрь 2025 г.», а не выдуманным первым числом (запрет 1 распространяется
  и на форматирование).
- **`sourceHref`: якорь `#page=N` только для PDF с `page > 0`** — `sourcePage = 0`
  это сентинел «страница не перепроверена» (вопрос 8): открываем документ целиком,
  в подписи страницу не показываем. Проверка вынесена в `hasConfirmedPage`.
- **`SourceLink` показывает sha256 префиксом (8 символов, полный — в title)
  и только когда бэк его вычислил** — пустой хэш из заглушек не рендерится.
- **`TooltipProvider` — глобально в `main.tsx`** — Base UI требует провайдера;
  один на приложение, а не по месту использования.
- **Дев-галерея `/dev/primitives` за `import.meta.env.DEV` + lazy-import** —
  флаг статически заменяется при сборке, чанк галереи в прод-бандл не попадает
  (проверено по выводу `vite build`). Галерея импортирует `seed-data` напрямую,
  минуя api-заглушки, — без ложных `STUB:`-warn'ов в консоли.
- **Тексты `InsufficientData` — в `constants/strings.ts`** — «это не ошибка» и
  «чего не хватает» юридически чувствительны, им место рядом с LEGAL_DISCLAIMER;
  причины отказа компонент принимает пропом `reasons` и не сочиняет сам.

## Сессия 5 (04.08.2026, линейная схема реки v1)

- **Схема — DOM/flex, а не SVG** — тултипы Base UI и `MeasurementValue` работают
  без foreignObject-обходов (риск «тултипы над SVG» снят), вертикальному списку
  узлов SVG ничего не даёт; в плане структура обновлена.
- **Выбор события: `?incident=` из URL, фолбэк — первое событие списка** — id
  заглушек не зашиваются в UI; лента и переключатель май/сентябрь начнут писать
  тот же параметр (deep-link решения сессии 1 уже работает на чтение).
- **Бар значения — длина, а не цвет; знаменатель — максимум события** —
  «относительное положение внутри выбранного события» (§13) без цветовой шкалы:
  формула цвета — открытый вопрос 10, а деление на максимум (не min–max)
  не обнуляет визуально минимальное значение.
- **Группа «порядок не подтверждён» — без линии, без ленты коридора и с явной
  текстовой оговоркой** — любая вертикальная последовательность читается как
  «по течению»; границы коридора отмечаются бейджами на самих створах,
  подзаголовок обещает «вверху — выше по течению» только когда упорядочены ВСЕ.
- **Лента коридора — слайсы строк между границами из `corridorBounds`** —
  фронт ничего не вычисляет (запрет 6), только рисует интервал; открытый вверх
  интервал (`upstreamStationId = null`) — лента от первой строки без верхней
  рамки, со стрелкой и подписью «открыт вверх по течению».
- **«Условный порядок» — только в дев-превью `/dev/river-scheme`** — ветку линии
  нельзя проверить на данных с `riverOrder = null`, поэтому в dev-сборке станциям
  присваиваются номера строк таблицы §5 с явной пометкой, что это разметка для
  вёрстки, а не порядок по течению; в прод-данные условный порядок не попадает.
- **`.playwright-mcp/` в `.gitignore`** — артефакты визуальных проверок
  пересоздаются каждую сессию, в репозитории им не место.

## Сессия 6 (04.08.2026, правая панель §13)

- **Выбор события вынесен в общий хук `src/hooks/use-selected-incident-detail.ts`** —
  панель и схема обязаны показывать одно и то же событие; две копии логики выбора
  разъехались бы при первом же изменении. Запросы дедуплицируются по ключу,
  поэтому «два вызова хука» ≠ «два запроса».
- **Один `StatementList` на блоки 3–4 вместо FactsList/RejectedList из плана** —
  рендер идентичен, различие только в данных (`supportedFacts` /
  `contradictedHypotheses`) и тексте пустого состояния; два компонента были бы
  копипастой.
- **Под каждым утверждением — его измерения-основания с кликабельными
  значениями** — текст утверждения приходит с бэка дословно и числа в нём не
  парсятся; вместо этого `panel-model.ts` разворачивает `measurementIds` в
  «створ + значение → документ», и критерий §16 п.5 выполняется и в панели.
- **Расшифровка уровня — видимым текстом, не только тултипом** — §13 требует
  «L0–L3 с расшифровкой»; на проекторе тултип не раскроют.
- **Пустые состояния блоков — осторожные формулировки в `constants/panel.ts`** —
  «Ни одна конкретная версия пока не исключена фактами» описывает состояние
  данных, а не чью-то невиновность; пустой блок не скрывается: порядок 1–6
  из `CONCLUSION_SECTIONS` — контракт, и отсутствие содержимого — тоже результат.
- **Страница в блоке «Источники» берётся из ссылающегося измерения** — у
  документа нет «своей» страницы; сентябрь получает «стр. 22», май скрыт
  сентинелом 0, новостные ссылки — без страницы.
- **`DATA_LOAD_ERROR` — общая строка в `constants/strings.ts`** — ошибка
  загрузки одинакова для всех колонок; `SCHEME_LOAD_ERROR` удалён.

## Сессия 7 (04.08.2026, лента сигналов и расследований)

- **Сигналы в ленте — под карточкой выбранного события, из его detail** —
  списковый `GET /api/incidents` сигналы не отдаёт (вопрос 2 открыт), а серия
  детальных запросов ради ленты дублировала бы данные; detail выбранного
  события уже загружен для схемы и панели, лента берёт его из кэша TanStack
  Query бесплатно. Ответ команды по вопросу 2 правит только contracts/api.
- **Карточка события — «растянутая кнопка» (after:inset-0), а не
  `<button>`-обёртка** — внутри карточки настоящие интерактивы (бейдж
  с тултипом, ссылки сигналов); вкладывать их в button — невалидный HTML.
  Так кликабельна вся карточка, клавиатура и `aria-current` работают штатно,
  а позиционированные бейдж/сигналы остаются кликабельными поверх кнопки.
- **Клик пишет `?incident=` push-навигацией** — история выбора листается
  кнопкой «назад», URL остаётся единственным источником истины; хук
  `use-selected-incident-detail` возвращает и `selectedIncidentId`, чтобы
  подсветка карточки не заводила вторую копию логики выбора.
- **`REGION_LABELS` — `constants/regions.ts`, ключи = значения API** — по
  образцу `PHENOMENON_LABELS`; подписи — области, как в заголовках
  бюллетеней Казгидромета.
- **Пустое состояние сигналов — «К событию не привязано ни одного публичного
  сигнала»** — описывает состояние данных, а не значимость события; строки
  ленты собраны в `constants/feed.ts`.

## Сессия 8 (04.08.2026, экран Актау «недостаточно данных»)

- **Экран «недостаточно данных» заменяет всю центральную колонку, включая
  заголовок «Линейная схема реки»** — для прибрежного кейса заголовок про
  реку был бы неправдой, а колонка с пустой рамкой читалась бы как ошибка;
  полноэкранное состояние — осознанный отказ (§13: жюри должно увидеть,
  что система не генерирует убедительный ответ без данных).
- **Триггер экрана — ноль створов у события, а не `region === 'mangystau'`** —
  «недостаточно данных» это свойство данных, не географии: атырауское событие
  без геометрии получит тот же экран, а мангистауское со створами — схему.
- **`InsufficientDataScreen` ничего не сочиняет: регион, заголовок, уровень,
  вывод и причины — из detail** — «что есть» (сообщения, модель волн) живёт
  только внутри дословного текста вывода; структурированное поле «что есть»
  потребовало бы выдумать данные, формат кейса — открытый вопрос 7.
- **Живёт в `features/aktau/`, но кейс не хардкодит** — папка по целевой
  структуре плана; имя компонента — по состоянию, не по городу.

## Сессия 9 (04.08.2026, реплей)

- **Позиция реплея хранится парой якорей (`anchorPositionMs` +
  `anchorTimeMs`), а не тикающим числом в сторе** — текущая позиция
  вычисляется от `performance.now()` при каждом чтении, поэтому пауза и
  перемотка не копят дрейф, а стор не перерисовывает подписчиков 60 раз
  в секунду. Тикающее значение живёт отдельно, в `useReplayPositionMs`.
- **Один `setTimeout` до абсолютного `offsetMs` следующего шага** — цепочка
  относительных таймеров дрейфует (подводный камень плана); задержка каждый
  раз пересчитывается от текущей позиции, а пауза и seek меняют зависимости
  эффекта, и таймер пересоздаётся сам.
- **Кадр реплея — селектор поверх загруженных данных, не отдельный запрос**
  (`useReplayFrame` + `projectDetailForReplay`): TanStack Query и реплей не
  смешиваются, на шаг не ходит ни один запрос. Кадр отдаётся только для
  своего `incidentId` — иначе сценарий сентября рисовался бы поверх мая.
- **Уровень и текст вывода во время реплея берутся из payload шага, а не
  из investigation** — уровни считает бэк (запрет 6), и промежуточные L0→L1→L2
  сценария §14 это тоже его данные; фронт их не выводит из измерений.
- **Скрываются измерения, документы и коридор; станции остаются** — сеть
  наблюдений это справочная основа кадра, а не накапливаемое доказательство:
  исчезающие створы читались бы как «данных нет», хотя вопрос в хронологии.
  Коридор привязан к шагу `inference`, потому что он и есть результат правила.
- **Пустые блоки панели во время реплея — «Появится на одном из следующих
  шагов реплея», а не скрытие блока** — порядок 1–6 из `CONCLUSION_SECTIONS`
  остаётся контрактом (решение сессии 3), и зритель видит, что вывод ещё
  не наступил, а не что его нет.
- **Сценарий читается `queryOptions`, хотя эндпоинт POST** — ТЗ §12 называет
  сценарий неизменяемым, а UI нужно знать заранее, есть ли он вообще: так
  кнопка play гаснет до нажатия, а не роняет ошибку после.
- **Клик по маркеру без запущенного реплея = ручной режим на этом шаге,
  без воспроизведения** — вести демо с проектора удобнее по шагам; тот же
  режим даёт «→» с клавиатуры. Пробел на кнопке/ссылке не перехватывается —
  это нативная активация, а не команда плеера.
- **Смена выбранного события гасит активный реплей** — сценарий одного
  события поверх данных другого рассинхронизировал бы все три колонки.
- **Play на завершённом реплее перезапускает с начала** — мёртвая кнопка
  в конце демо хуже, чем повтор; статус `finished` отличим от `paused`.
- **`min-w-0` на `<footer>`** — как строка грида футер получал минимальную

  Строка шага — блок с `truncate`, а не flex: у flex-контейнера минимальная
  ширина всё равно считается по детям.

## Сессия 10 (04.08.2026, переключение май/сентябрь)

- **Период события добавлен в провизорный контракт (`IncidentSummary.period`),
  а не вычислен из заголовка** — списковый ответ не отличал май от сентября,

- **Во время реплея плашка не показывается** — у реплея своя хронология,

## Сессия 13 (04.08.2026, переезд на packages/contracts + API-слой F2)

- **Форма данных приходит из `packages/contracts`, а не описывается у нас** —
  собственные `src/types/*` удалены, остался баррель-реэкспорт. Схема, которая
  исполняется, сильнее типа, который только описан: расхождение теперь падает
  на `parse`, а не всплывает на демо. `src/api/contracts.ts` оставлен тонким
  слоем — если пакет переименуют или разделят, правка будет в одном файле.
- **Данные и оценки бэкендера приоритетнее наших** — сентябрь понижен до L1,
  коридор и опровергнутая версия убраны, статус сигнала стал `corroborated`,
  тексты шагов реплея взяты из фикстуры. Уровни считает бэк (запрет 6 CLAUDE.md),
  и это распространяется на всё, что из уровня следует. Свои у нас остались
  только те данные, которых у бэка ещё нет (май, Актау).
- **Сентябрьский L2 не «сломался», а стал недоступен** — пространственный вывод
  («источник выше створа X») требует подтверждённого порядка створов, а его нет.
  Ветки UI под коридор и блок «не подтверждается» живы и проверены на майском
  кейсе: вернуть картинку можно правкой сида, без кода.
- **Zod во фронте не объявляется зависимостью** — схемы приходят из пакета,
  который zod уже тянет. Там, где нужен тип схемы, стоит структурный
  `ResponseSchema<T> = { parse: (value: unknown) => T }`: фронт не знает, какой
  библиотекой проверен ответ, и не привязывается к её мажору.
- **Сид проверяется теми же схемами, что и ответ сети** (`parseSeed`) — офлайн-
  данные это тоже «ответ», просто из файла. Иначе seed-режим тихо разъезжается
  с контрактом, и узнаём мы об этом в момент интеграции, а не в момент правки.
- **`VITE_DATA_MODE` по умолчанию `seed`, а не `api`** — вопреки букве контракта
  команды. Read-эндпоинтов ещё нет, а критерий приёмки требует работы без
  бэкенда и без `.env`; запросы к несуществующему `/api` выглядели бы на экране
  как поломка данных. Дефолт меняется одной строкой в `constants/api.ts`
  после контрольной точки C.
- **Отмена запроса не является ошибкой** — при aborted-сигнале вызывающего
  наверх уходит исходный `AbortError`, и TanStack Query трактует его как отмену.
  Таймаут — наоборот, настоящая `ApiRequestError` с кодом `TIMEOUT`: «мы не
  дождались» и «мы передумали» на экране должны выглядеть по-разному.
- **Расхождение ответа со схемой — громкая ошибка, а не тихая деградация**
  (`INVALID_RESPONSE` с текстом от Zod): молча отрисованная половина полей
  на демо хуже честного сообщения о сбое интеграции.
- **Ключи запросов собираются фабрикой `queryKeys`** — опечатка в строковом
  литерале ключа не ломает сборку, зато заводит второй кэш того же запроса.
- **`provenance` печатается из `DossierModel`, а не из `IncidentDetail`** —
  в утверждённой схеме detail этих полей нет, они едут с машиночитаемым досье.
  Печатная страница осталась независимой от эндпоинта экспорта (решение
  сессии 1), поэтому в модели стоит явная пара `null` с комментарием, а не
  запрос к `/export`.
- **`sourceExcerpt` измерений обнулён** — схема разрешает `verified: true`
  только с настоящей выдержкой из документа, а у нас там была реконструкция
  строки таблицы. Правдоподобная цитата хуже отсутствующей: она выглядит как
  проверенная.
- **Связи створов (`relationType`, `relatedObjectId`) обнулены** вслед за
  фикстурой — «выше/ниже сброса» остаётся видимым текстом в названии створа,
  но не машинным утверждением, под которое нет provenance. UI их всё равно
  не читает, так что цена нулевая, а честность отчётливая.
- **CLAUDE.md восстановлен при слиянии** — в ветке бэкенда файл удалён, но его
  удаление пришло из чужой рабочей копии (видно в его же отчёте), а не было
  решением. Файл описывает зоны ответственности троих разработчиков.
- **Workspace-зависимость `@caspian-trace/contracts` добавлена самостоятельно**,
  хотя `package-lock.json` — зона Full-stack 1: без неё переезд невозможен,
  а новых внешних пакетов правка не вносит. Full-stack 1 предупреждён отдельным
  пунктом в `docs/questions-to-fullstack.md`.
- **Уязвимость `react-router` (2 high) не чинится перед демо** — `audit fix
  --force` ломает мажор роутера, на котором стоят все маршруты и deep-link;

## Сессия 15 (05.08.2026, состояния источников F6 + пометка заглушек)

- **Состояние источника кодируется формой метки, а не цветом** — пять
  начертаний (круг, кольцо, квадрат, ромб, пунктирный круг). Красная точка
  «источник упал» ввела бы в ахроматический хром (решение сессии 3) первый
  цвет, и на проекторе рядом со схемой реки она читалась бы как шкала
  «опасности» — ровно то, что запрещает запрет 4. Смысл несёт подпись,
  метка её поддерживает; на монохромном проекторе форма различается, цвет нет.
- **Индикатор живёт в шапке, а не в колонке** — состояние источников относится
  ко всему экрану и не зависит от выбранного события. Кнопка ушла в `-my-1`,
  чтобы шапка осталась 41 px и линия `border-b` не разъехалась с колонками
  (тот же приём, что у кнопки «Досье», решение сессии 12).
- **Оговорка «недоступный источник — это пробел в данных, а не отсутствие
  события» стоит первой строкой поповера** — поповер прокручивается, а именно
  эта строка отделяет «источник недоступен» от «событий нет» (цель F6).
  Всё, что оказалось ниже фолда, на демо не прочитают.
- **Пометка «заглушки» — бейдж в шапке плюс реестр в поповере, а не надпись
  поверх экрана** — просьба владельца продукта выполнена так, чтобы она не
  превратилась в неправду: значения в сиде настоящие (бюллетени §5, с sha256,
  страницами и выдержками), заглушкой является ТРАНСПОРТ. Поэтому текст
  разводит два смысла: «числа не выдуманы… заглушка это способ доставки,
  а не источник данных».
- **Реестр заглушек продублирован в код (`constants/stubs.ts`), а не вычитан
  из `docs/stubs.md`** — документ подробнее и содержит то, чего на экране нет
  (например, `evidence`, который UI не потребляет). Экранный список отвечает
  на один вопрос: что из видимого сейчас приходит из файла и какой эндпоинт
  это заменит. Расхождение двух списков лечится тем, что оба правятся в конце
  сессии по одному чек-листу.
- **Реестр показывается и в api-режиме** — тогда он отвечает на другой вопрос:
  какие эндпоинты уже подняты. Пустая колонка в api-режиме имеет ровно эту
  причину, и искать её в консоли не придётся.
- **Одинаковая расшифровка статуса печатается один раз на группу** — список
  отсортирован по состоянию, поэтому одинаковые идут подряд; четыре одинаковых
  абзаца — шум, а не подсказка (тот же довод, что у отменённых тултипов-дублей,
  решение сессии 12).
- **`SourceHealthMarkIcon` принимает начертание, а не статус** — «состояние
  неизвестно» (запрос идёт или упал) рисуется тем же пунктиром, что и
  `never_run`, но статусом не является: обе метки говорят одно — успешного
  опроса не было.
- **Сбой `GET /api/live/status` не роняет экран и не показывается ошибкой** —
  это состояние источников, а не поломка приложения: индикатор пишет
  «состояние источников не получено», остальные колонки живут как жили.
- **Синтетические источники — только в дев-превью** (как «условный порядок»
  створов, решение сессии 5): в сиде все четыре источника `never_run`, и
  дорисовывать «зелёные» ради красивой картинки нельзя — экран показывал бы
  опросы, которых не было.

  0.01ms`, не `animation: none`): компоненты Base UI закрываются по
  `animationend`, и без события поповер остался бы открытым навсегда.

  содержит истории `feat/backend-investigation`: работу Backend 2 туда перенесли

  БД, которую нечем проверить, — тот же случай, что в сессии 17: «помочь» здесь
  значит подложить тихую поломку в чужую зону.
- **Процент вероятности по названному предприятию не выводится** — это отказ
  от прямой формулировки задачи, и он обоснован не стилем, а тем, что числа
  нет: ядро выпускает уровни L0–L3 и утверждения правил, фронт выводы не считает
  (запрет 6). Любой процент на экране был бы придуман здесь и стоял бы рядом
  с именем настоящего юрлица. Показываем то, что система действительно
  вычисляет: объект внутри участка или вне его, плюс уровень и дословный текст
  правила. Это и есть «какие предприятия могли бы» из ТЗ — поле
  `candidateObjects` заведено ровно для этого.
- **Событие демо — сентябрь, а не май** — решение принято после сверки данных,
  а не по вкусу: у мая один объект-кандидат и ноль исключённых версий, то есть
  сюжет «агент проверил очевидного подозреваемого и отбросил его» там не
  собирается вовсе.
- **Положение объекта на карте выводится из подписей створов и это печатается
  пользователю** — координат у объектов нет, но створы бюллетеня называются
  «0,5 км выше сброса» и «0,5 км ниже сброса», то есть документ сам помещает
  сброс между ними. Вывод остаётся визуальным и подписанным, в данные он не
  попадает: решение сессии 13 (связи створов не кодируются машинным полем без
  provenance) не отменяется.
- **Створ или объект без подтверждённого места в цепочке на карту не
  выносится вовсе** — поставить точку наугад значило бы выдумать координаты
  (запрет 2). Три сентябрьских створа и Осетровый завод остаются вне карты.
- **MapLibre GL поставлен по прямому решению владельца продукта, вопреки моей
  рекомендации** — я возражал трижды: координат нет, офлайн-тайлов нет,
  `package-lock.json` чужая зона. Возражения сняты решением; правка lockfile
  сделана и вынесена отдельным пунктом в `docs/questions-to-fullstack.md`.
- **Подложка OSM — осознанное отступление от критерия «демо работает без
  интернета»** — тоже решение владельца продукта. Ломается при этом только
  картинка подложки: наши слои, маркеры, значения и весь остальной экран
  офлайн продолжают работать, поэтому ошибки тайлов гасятся и в консоль
  не сыпятся. Атрибуция OpenStreetMap включена — это условие использования.
- **Стиль карты задан инлайн, подписи — HTML-маркерами, а не symbol-слоями** —
  symbol требует шрифтовых PBF по `glyphs`, то есть второго сетевого источника.
  Маркерами же тултипы Base UI и `MeasurementValue` работают как везде.
- **Карта живёт в state, а не в ref** — в StrictMode эффект монтируется дважды,
  карта пересоздаётся, и эффект данных обязан переисполниться на новом
  экземпляре. С ref он этого не замечал: слои заводились, а данные уходили
  в уже удалённую карту, и линии не рисовались при пустой консоли.
- **`optimizeDeps.exclude: ['maplibre-gl']`** — оптимизатор Vite не переносит
  воркер MapLibre в `.vite/deps`, из-за чего источник GeoJSON вечно остаётся
  «не загружен». Симптом обманчив: DOM-маркеры видны, ошибок нет, а слои пусты.
- **Вкладки заведены и сняты в одну сессию** — вкладка агента отложена
  владельцем продукта, карта переехала в центральную колонку, и таб-бар с одной
  оставшейся вкладкой читался бы как сломанный элемент. Механика снята целиком;
  вернуть её дешевле из истории, чем держать мёртвой.
- **Оговорка про демо-координаты живёт в реестре «Состояние данных», а не
  плашкой на карте** — «что на экране не из проверенных данных» должно быть
  одним списком, а не метками по всему интерфейсу. Убрать оговорку совсем
  было нельзя: на настоящей карте города выдуманные позиции читаются как
  проверенные.
- **Карточка вывода поверх карты убрана как дубль** — после переезда карты
  в центр она дословно повторяла правую панель, где уже стоят уровень, вывод
  и «что не подтверждается» (принцип сессии 18 «один факт — одно место»).
- **Имя створа на карте усекается, значение — никогда** — колонка узкая,
  названия длинные, а обрезанное значение было бы обрезанным доказательством.
  Полное имя остаётся в `title`, в правой панели и в таблице досье.
- **Линейная схема реки не удалена** — она цела, покрыта дев-превью и
  возвращается одной строкой в `App.tsx`: карта стоит на демонстрационных
  координатах, и путь назад обязан быть дешёвым.
