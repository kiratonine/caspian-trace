# Мультиязычность ru/kk/az/fa/tk — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** интерфейс «Каспийского следа» читается на русском, казахском, азербайджанском, персидском и туркменском языках; язык переключается кнопкой в правом краю шапки.

**Architecture:** i18next + react-i18next, ресурсы — TS-модули, статически вкомпилированные в бандл (демо офлайн). Структура справочников `src/constants/` остаётся кодом (порядок блоков §13, состав досье §21.1, тон палитры §6), в ресурсы уезжает только текст. Текст данных (выводы, утверждения, названия створов) переводится чистым селектором поверх кэша TanStack Query, а не на границе `src/api/`.

**Tech Stack:** React 19, TypeScript strict, Vite 8, Tailwind 4, Base UI, i18next, react-i18next, @fontsource-variable/vazirmatn.

**Спека:** `docs/superpowers/specs/2026-08-06-i18n-design.md` — читать целиком перед началом.

## Global Constraints

- Рабочая ветка — `frontend`. Правим только `apps/web/**` и `docs/**`. Не трогаем `apps/api/**`, `packages/**`, `data/verified/**`.
- Все проверки гонять **с `-w web`**: корневые `npm run typecheck` и `npm run build` падают на `apps/api` (bash-подстановка `${DIRECT_URL:-...}` в его `prisma:generate`, cmd.exe её не понимает).
- **Ни одной строки ПЕРЕВОДИМОГО текста на верхнем уровне модуля.** Текст интерфейса берётся только во время рендера: `useTranslation()` в компоненте либо чистая функция с локалью в аргументе. Константа вида `export const X = i18n.t(...)` застынет на языке первой загрузки — это баг, а не стиль. Литералы, которые по определению одинаковы во всех локалях, под правило не подпадают и остаются в модуле: `LOCALE_ENDONYMS` (فارسی — это فارسی в любом интерфейсе), `app.name` «Caspian Trace», названия юрлиц.
- **Числа форматируются `ru-RU` на всех пяти языках.** Константа `NUMBER_LOCALE`. Причина: число на экране обязано сверяться с таблицей бюллетеня (решение сессии 4). Локализуется только единица измерения рядом с ним.
- **Имена собственные не переводятся:** `CandidateObject.name` («КГП «Атырау су арнасы»», «Осетровый завод»), «GDELT DOC 2.0», «Open-Meteo Flood API», «Казгидромет». Механизм — отсутствие ключа в таблице данных, фолбэк печатает оригинал.
- **Запрещённые смыслы в любом языке:** «виновен», «нарушитель», «загрязнитель», «источник установлен», «доказано». Формулировка `OBJECT_FOR_REVIEW_LABEL` строится нейтральным залогом — «объект, подлежащий проверке».
- Отсутствие перевода = печатается оригинал. Пустая строка на экране недопустима.
- Зона `Asia/Atyrau` фиксирована и от локали не зависит.
- Комментарии в коде остаются русскими — это заметки разработчикам, а не интерфейс.
- Коммиты — по-русски, префиксами conventional commits, как в истории ветки.

## Чем заменён TDD

**Тестового раннера в `apps/web` нет** (вопрос 15 к Full-stack 1 открыт, тестовая инфраструктура — его зона). Ставить vitest этим планом не будем: выбор раннера принадлежит владельцу `packages/**`, а задача и без того большая. Вместо этого красно-зелёный цикл даёт **`tsc -b`**, и он здесь не формальность:

- каждая нерусская локаль объявлена `satisfies typeof ru`;
- `declare module "i18next"` типизирует сам `t()`.

Пропущенный ключ в казахском и опечатка в ключе — это падение сборки, а не пустая строка на проекторе. Поэтому шаги «убедиться, что падает» и «убедиться, что собралось» в задачах ниже — настоящий цикл, а не ритуал.

Визуальная проверка идёт через дев-галерею `/dev/i18n` (Task 13) — та же конвенция, что у `/dev/primitives`, `/dev/river-scheme`, `/dev/live-status`, `/dev/comparison`.

## Оговорка про объём переводов

```ts
// Список локалей и всё, что от него производно. Отдельный файл без импортов
// i18next: его читают и форматтеры, и роутер, и дев-галерея.

export const LOCALES = ["ru", "kk", "az", "fa", "tk"] as const

export type Locale = (typeof LOCALES)[number]

export const DEFAULT_LOCALE: Locale = "ru"

// Персидский — единственное письмо справа налево из пяти.
export const RTL_LOCALES: readonly Locale[] = ["fa"]

// Эндонимы: носитель ищет свой язык написанным по-своему, а не «Персидский»
// кириллицей. Порядок — как в LOCALES.
export const LOCALE_ENDONYMS = {
  ru: "Русский",
  kk: "Қазақша",
  az: "Azərbaycanca",
  fa: "فارسی",
  tk: "Türkmençe",
} as const satisfies Record<Locale, string>

// Локаль для Intl НЕ равна коду локали интерфейса. Персидский форсируется на
// григорианский календарь и европейские цифры: по умолчанию Intl отдал бы
// джалали («۱۸ شهریور ۱۴۰۴»), а демо стоит на сентябрьском бюллетене — дату,
// которую нельзя сопоставить с документом, показывать нельзя.
export const INTL_LOCALES = {
  ru: "ru-RU",
  kk: "kk-KZ",
  az: "az-AZ",
  fa: "fa-IR-u-ca-gregory-nu-latn",
  tk: "tk-TM",
} as const satisfies Record<Locale, string>

// Числа не локализуются вообще: значение на экране обязано сверяться
// с таблицей бюллетеня (решение сессии 4). Запятая как десятичный разделитель
// верна и для kk, az, tk; фарси получил бы арабо-индийские цифры.
export const NUMBER_LOCALE = "ru-RU"

export function isRtl(locale: Locale): boolean {
  return RTL_LOCALES.includes(locale)
}

export function isLocale(value: unknown): value is Locale {
  return typeof value === "string" && (LOCALES as readonly string[]).includes(value)
}
```

- [ ] **Step 1: Создать `src/i18n/resolve-initial-locale.ts`**

Функция чистая и принимает окружение аргументом, а не читает `window`: так её поведение видно из сигнатуры и её можно вызвать из дев-галереи.

```ts
import { DEFAULT_LOCALE, isLocale, type Locale } from "./config"

export const LOCALE_STORAGE_KEY = "caspian-trace:locale"

export const LOCALE_SEARCH_PARAM = "lang"

type LocaleEnvironment = {
  search: string
  stored: string | null
  navigatorLanguages: readonly string[]
}

/**
 * Приоритет: ?lang= → localStorage → язык браузера → русский.
 *
 * Параметр URL уважается при чтении, но в адрес не дописывается: ссылку
 * с заранее выставленным языком можно отправить судье, а обычные ссылки
 * на события не обрастают вторым параметром рядом с ?incident=.
 */
export function resolveInitialLocale(env: LocaleEnvironment): Locale {
  const fromUrl = new URLSearchParams(env.search).get(LOCALE_SEARCH_PARAM)
  if (isLocale(fromUrl)) return fromUrl

  if (isLocale(env.stored)) return env.stored

  for (const language of env.navigatorLanguages) {
    // 'kk-KZ' → 'kk'. Регион игнорируем: локаль у нас одна на язык.
    const base = language.split("-")[0]?.toLowerCase()
    if (isLocale(base)) return base
  }

  return DEFAULT_LOCALE
}
```

- [ ] **Step 3: Создать `src/i18n/use-locale.ts`**

```ts
import { useCallback } from "react"
import { useTranslation } from "react-i18next"

import { DEFAULT_LOCALE, isLocale, type Locale } from "./config"
import { LOCALE_STORAGE_KEY } from "./resolve-initial-locale"

export function useLocale(): {
  locale: Locale
  setLocale: (locale: Locale) => void
} {
  const { i18n } = useTranslation()

  // i18n.language может нести регион ('ru-RU') после смены языка браузером;
  // наружу отдаём только известную локаль.
  const locale = isLocale(i18n.language) ? i18n.language : DEFAULT_LOCALE

  const setLocale = useCallback(
    (next: Locale) => {
      void i18n.changeLanguage(next)
      window.localStorage.setItem(LOCALE_STORAGE_KEY, next)
```

Форматтеры кэшируются по локали: `Intl.DateTimeFormat` дорог, а локаль меняется редко.

```ts
import { INTL_LOCALES, NUMBER_LOCALE, type Locale } from "@/i18n/config"

const TIME_ZONE = "Asia/Atyrau"

// Числа не локализуются: значение на экране обязано сверяться с таблицей
// бюллетеня (решение сессии 4). Персидская локаль отдала бы ۰٫۲۳۴.
const numberFormat = new Intl.NumberFormat(NUMBER_LOCALE, {
  maximumFractionDigits: 3,
})

const dateFormats = new Map<Locale, Intl.DateTimeFormat>()
const dateTimeFormats = new Map<Locale, Intl.DateTimeFormat>()
const monthFormats = new Map<Locale, Intl.DateTimeFormat>()

function cached(
  cache: Map<Locale, Intl.DateTimeFormat>,
  locale: Locale,
  options: Intl.DateTimeFormatOptions
): Intl.DateTimeFormat {
  const hit = cache.get(locale)
  if (hit) return hit
  const created = new Intl.DateTimeFormat(INTL_LOCALES[locale], {
    timeZone: TIME_ZONE,
    ...options,
  })
  cache.set(locale, created)
  return created
}

export function formatNumber(value: number): string {
  return numberFormat.format(value)
}

export function formatDate(iso: string, locale: Locale): string {
  return cached(dateFormats, locale, {
    day: "numeric",
    month: "long",
    year: "numeric",
  }).format(new Date(iso))
}
```
