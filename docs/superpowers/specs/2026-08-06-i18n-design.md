# Мультиязычность интерфейса: ru / kk / az / fa / tk

Дата: 06.08.2026. Автор: фронтенд. Статус: согласовано владельцем продукта.

## Задача

Жюри конкурса — из разных стран Каспийского региона. Интерфейс должен читаться
на русском, казахском, азербайджанском, персидском и туркменском языках,
с переключателем языка в правом краю шапки.

Решение владельца продукта 06.08.2026: **переводится всё**, включая текст,
который приходит данными с бэкенда (выводы, утверждения, названия створов,
заголовки событий, шаги реплея), а не только хром интерфейса.

## Языки

| Код | Язык | Эндоним | Письмо | Направление |
| --- | --- | --- | --- | --- |
| `ru` | Русский | Русский | кириллица | LTR |
| `kk` | Казахский | Қазақша | кириллица | LTR |
| `az` | Азербайджанский | Azərbaycanca | латиница | LTR |
| `fa` | Персидский | فارسی | арабское | RTL |
| `tk` | Туркменский | Türkmençe | латиница | LTR |

Казахский берётся **кириллицей**: это действующее официальное письмо в РК
(переход на латиницу идёт до 2031 года), и первоисточники продукта — бюллетени
Казгидромета — тоже кириллические. Азербайджанский и туркменский — латиница,
альтернатив нет.

Русский остаётся языком по умолчанию и языком фолбэка.

## Зависимости

Владелец продукта разрешил установку в этой сессии (`package-lock.json` —
зона Full-stack 1, его надо предупредить отдельно, см. «Координация»).

- `i18next` + `react-i18next` — ядро и биндинги React (≈ 55 kB min).
- `@fontsource-variable/vazirmatn` — шрифт для арабского письма (≈ 150 kB).
  Inter, уже лежащий в бандле, покрывает кириллицу с казахскими литерами
  (ә ғ қ ң ө ұ ү һ і) и латиницу с диакритикой (ə ğ ı ş ü / ä ň ý ž), то есть
  kk, az и tk закрыты бесплатно. Арабское письмо Inter не покрывает: без
  Vazirmatn фарси отрисуется системным шрифтом и выпадет из типографики.
- `npx shadcn@latest add select` — компонент переключателя (Base UI, свободно
  по CLAUDE.md, зависимостью не считается).

**Не берём осознанно:**

- `i18next-http-backend` — грузит ресурсы по сети. Прямое нарушение критерия
  приёмки «демо работает без интернета».
- `i18next-browser-languagedetector` — детект языка это десять строк своего
  кода, отдельная зависимость их не стоит.

Ожидаемая цена бандла: 1884 kB → ≈ 2150 kB (ресурсы пяти языков ≈ 60–80 kB).
Записать по факту, как записывали цену карты в сессии 19.

## Архитектура

### Структура модуля

```
src/i18n/
  config.ts        LOCALES, DEFAULT_LOCALE, RTL_LOCALES, тип Locale
  index.ts         инициализация i18next (без плагинов, ресурсы статически)
  i18next.d.ts     declare module 'i18next' → t() типизирован ключами ru
  use-locale.ts    текущая локаль, смена, запись в localStorage
  resources/
    ru.ts          источник истины типа
    kk.ts az.ts fa.ts tk.ts    объявлены `satisfies typeof ru`
  data/
    ru.ts kk.ts az.ts fa.ts tk.ts    переводы данных, ключ = id сущности
    translate.ts   чистые селекторы поверх загруженных данных
```

### Ресурсы — TS-модули, а не JSON

Русский ресурс становится источником истины типа, остальные объявляются
`satisfies typeof ru`. Пропущенный ключ в казахском — это падение `tsc -b`,
а не пустая строка на проекторе во время демо. С JSON-импортами такой гарантии
нет. `declare module 'i18next'` дополнительно типизирует сам `t()`: опечатка
в ключе тоже не собирается.

### Хром: структура остаётся в константах, уезжает только текст

Отвергнут классический подход «все строки в плоские ключи»: справочники
`src/constants/` здесь не строки, а контракты. `CONCLUSION_SECTIONS` задаёт
порядок блоков ТЗ §13 (решение сессии 3), `DOSSIER_SECTIONS` — состав 12 пунктов
роадмапа §21.1 с флагом `lead` (решение сессии 12), `EVIDENCE_LEVEL_META` несёт
`tone` палитры §6 рядом с текстом. Разобрав их на ключи, мы потеряли бы свойство
«массив и есть контракт» и получили бы возможность молча уронить блок §13
при переводе.

Поэтому:

- `CONCLUSION_SECTIONS` → `[{ id: "conclusion" }, …]`; заголовок берётся
  `t('panel.section.' + section.id + '.title')`.
- `EVIDENCE_LEVEL_META` → сохраняет `code` и `tone`; `label` и `description`
  уезжают в ресурс под ключами `evidence.L0…L3`.
- `DOSSIER_SECTIONS` → сохраняет `id` и `lead`; все 12 заголовков в ресурсе.

Переводчик правит только значения и физически не может изменить состав
или порядок.

### Жёсткое правило: ни одной строки текста на верхнем уровне модуля

Сегодня `PANEL_NO_FACTS` — константа, вычисленная при импорте. Если она станет
`i18n.t(...)` на том же месте, она навсегда застынет на языке первой загрузки.
Текст берётся **только во время рендера**: через `useTranslation()` в компоненте
либо чистой функцией, которой локаль передана аргументом. Скрытых чтений
глобального экземпляра `i18n` в модульной области быть не должно.

Правило добавляется в CLAUDE.md вместе с остальными конвенциями.

### Форматирование

Хук `useFormat()` отдаёт связанные с текущей локалью `formatDate`, `formatMonth`,
`formatDateTime`, `formatMeasurement`. Под ним остаются чистые функции с явным
параметром локали — их зовёт досье и весь код вне React.

### Данные: селектор при рендере, а не перевод на границе `src/api/`

Это продолжение решения сессии 9 (`projectDetailForReplay` — селектор поверх
загруженных данных, а не второй запрос). Ответ кэшируется TanStack Query один
раз, перевод накладывается чистой функцией сверху. Альтернатива — переводить
сразу после `parse` — потребовала бы вписать язык в `queryKeys`, и смена языка
стала бы новым сетевым запросом в api-режиме.

Таблица переводов ключуется `id` сущности, пришедшим с бэка:

```
incident   → title, conclusionText
statement  → text
station    → name
document   → title
signal     → title, quote
replayStep → text
liveSource → name
unknown    → text
region     → label
```

**Отсутствие перевода = оригинал, никогда не пустая строка.** Это же и механизм
защиты имён собственных: у `CandidateObject.name` («КГП «Атырау су арнасы»»,
«Осетровый завод»), у «GDELT DOC 2.0» и «Open-Meteo Flood API» в таблице просто
нет ключей, поэтому они печатаются как есть на любом языке. Переводить название
юридического лица нельзя — это ровно то искажение, от которого страхует ТЗ §4.

### Дословные выдержки печатаются вместе с оригиналом

`Measurement.sourceExcerpt` и цитата сигнала: перевод — основным текстом,
русский оригинал — мельче под ним. Причина не в качестве перевода, а в
сверяемости: рядом со ссылкой «стр. 22» и SHA-256 бюллетеня не должно стоять
текста, которого в том PDF нет. Это единственное место, где оригинал
показывается рядом с переводом.

## Форматы

### Числа не локализуются

`Intl.NumberFormat('fa')` вернул бы `۰٫۲۳۴` арабо-индийскими цифрами, и число
перестало бы сверяться с таблицей бюллетеня. Решение сессии 4 («число на экране
1:1 с первоисточником») сильнее локали: форматирование остаётся `ru-RU` на всех
пяти языках. Побочно это верно и типографически — запятая как десятичный
разделитель принята в kk, az и tk. Локализуется только единица измерения
рядом с числом (мг/дм³ → mg/dm³).

### Даты: фарси форсируется на григорианский календарь

`Intl.DateTimeFormat('fa')` по умолчанию переключается на **персидский
(джалали) календарь**: «9 сентября 2025 г.» превратилось бы в
«۱۸ شهریور ۱۴۰۴». Демо стоит на сентябрьском бюллетене, и дата, которую нельзя
сопоставить с документом, — потеря факта. Локаль для фарси форсируется как
`fa-u-ca-gregory-nu-latn`: григорианский календарь, европейские цифры,
персидские названия месяцев.

Зона `Asia/Atyrau` остаётся фиксированной (решение сессии 4), от локали
не зависит.

### RTL — только внутри текста

Решение владельца продукта: макет остаётся LTR. Лента слева, карта в центре,
панель справа, шкала реплея слева направо — хронология доказательств и течение
реки не зеркалятся.

- `<html lang>` проставляется всегда: от него зависят подбор шрифта, переносы
  и скринридер.
- `dir="auto"` ставится на все узлы с текстом **данных**. Тогда вывод, у которого
  нет перевода и который упал в русский оригинал, внутри персидского интерфейса
  всё равно отрисуется слева направо.
- `dir="rtl"` — на текстовых контейнерах хрома при `fa`.
- Выравнивание переводится с `left`/`right` на логические `start`/`end` там,
  где это текст. Сетка трёх колонок, карта и шкала реплея не трогаются.
- Vazirmatn добавляется **вторым** в `--font-sans` для всех локалей, а не
  условным правилом для `fa`. Подбор шрифта в браузере идёт по глифам:
  Inter не содержит арабского письма, и персидские символы сами провалятся
  в Vazirmatn. Правило `html[lang="fa"]` не нужно, и смешанная строка
  (персидский текст с латинским «Caspian Trace» внутри) отрисуется
  правильными шрифтами по частям.

## Переключатель языка

- Живёт в правом краю шапки (`ml-auto`), рядом с индикатором источников.
- Триггер: иконка глобуса + код текущего языка (`RU`). В `-my-1`, чтобы шапка
  осталась 41 px и линия `border-b` не разъехалась с колонками (решение
  сессии 12).
- Список — **эндонимы**: Русский · Қазақша · Azərbaycanca · فارسی · Türkmençe.
  Носитель ищет свой язык написанным по-своему, а не «Персидский» кириллицей.
- Компонент — shadcn `select` на Base UI.
- Доступен с клавиатуры, у триггера `aria-label`.

### Хранение выбора

Приоритет: параметр URL `?lang=` → `localStorage` → совпадение с
`navigator.language` → `ru`.

`?lang=` уважается при чтении, но **в URL не дописывается**: ссылку с заранее
выставленным языком можно отправить судье, но обычные ссылки на события
не обрастают вторым параметром рядом с `?incident=`.

## Досье

Печатается целиком на текущем языке, включая юридическую оговорку
`LEGAL_DISCLAIMER`. Печатные стили (`@media print`, `@page A4`, решение
сессии 12) не меняются; `<html lang>` и `dir` действуют и при печати.

## Порядок сдачи

Замер по коду на 06.08.2026 — строки с русским текстом вне комментариев,
без `dev/` и `seed-data.ts`:

| Область | Строк |
| --- | --- |
| `src/constants/` | 201 |
| `src/features/` | 61 |
| `src/api/` | 16 |
| `src/components/` | 10 |
| **Итого хром** | **288** |

Плюс ≈ 40 текстовых полей данных в `seed-data.ts`. На четыре новые локали это
порядка 1300 переводов.

Важно, что 71 строка из 288 лежит **не в `constants/`**: это inline-текст в JSX
и `aria-label`'ы компонентов (например, `aria-label="Вывод и доказательства"`
в `ConclusionPanel.tsx` рядом с таким же видимым заголовком). Их легко
пропустить при переводе — экран будет выглядеть переведённым, а скринридер
продолжит читать по-русски. План обязан пройти по этим четырём областям
списком файлов, а не «по экранам».

Одним куском это не проверяется, поэтому работа делится на три шага, каждый
проверяем и коммитится отдельно.

1. **Инфраструктура + русский + переключатель.** Весь текст уже ходит через
   `t()`, `tsc -b` держит ключи, экран работает на одном языке. Переключатель
   стоит и переключает, остальные локали пока копия русского.
2. **Казахский и азербайджанский.** Первая настоящая проверка на длину строк:
   обе локали длиннее русского.
3. **Персидский и туркменский.** Шрифт Vazirmatn, `dir`, форсированный
   календарь.

## Проверка

На каждом шаге:

- `npm run typecheck -w web`, `lint -w web`, `prettier --check`, `build -w web`
  (корневые команды падают на `apps/api` после слияния сессии 19).
- Главный экран (сентябрь и май), экран Актау, досье — на 1280×720 в светлой
  и тёмной теме, без горизонтальной прокрутки.
- Консоль без ошибок, только `STUB:`-варны.
- `aria-label` и прочие невидимые строки — отдельным проходом по дереву
  доступности, а не глазами по экрану: переведённая картинка при русском
  скринридере выглядит готовой работой и таковой не является.

Отдельно на шаге 2:

- Бейдж L3 «Коридор поддержан лабораторными данными» — он единственная видимая
  расшифровка §13 (решение сессии 18), а казахский и азербайджанский длиннее
  русского. Ручной чек-лист сессии 18 уже помечал его подозрительным на
  обрезание при ~1100 px; после перевода проверить обязательно, замером
  ширины, а не `innerText` (усечение CSS `innerText` не ловит).
- Карточки ленты и заголовки блоков панели — не выросли ли на строку.

Отдельно на шаге 3:

- Числа в персидской локали — европейскими цифрами (`0,234`, не `۰٫۲۳۴`).
- Даты — григорианские («سپتامبر ۲۰۲۵» недопустим в форме джалали
  `شهریور ۱۴۰۴`).
- Непереведённый текст данных внутри персидского интерфейса отрисован LTR
  (проверяется временным удалением ключа).
- Шрифт: `document.fonts.check` на Vazirmatn, а не глазами.

## Риски, принятые осознанно

1. **Переводы не вычитаны носителями языка.** Их делает ассистент.
   Владелец продукта 06.08.2026 отказался от видимой пометки «перевод не
   заверен» — переводы подаются как равноправные версии. Наибольший риск
   несут `LEGAL_DISCLAIMER` и формулировка `OBJECT_FOR_REVIEW_LABEL`
   («объект для проверки»): неточный перевод может прочитаться как обвинение,
   что нарушает запрет 3 CLAUDE.md на чужом языке, не нарушая его на русском.
   Смягчение: в каждой локали формулировка строится как «объект, подлежащий
   проверке» (нейтральный залог), без слов со значением «виновный»,
   «нарушитель», «загрязнитель».
   **Отдельный результат работы — файл `docs/i18n-legal-strings.md`:** таблица
   пяти юридически чувствительных строк (`LEGAL_DISCLAIMER`,
   `OBJECT_FOR_REVIEW_LABEL`, `INSUFFICIENT_DATA_EXPLANATION`, расшифровка L3
   «Не означает, что виновник установлен», пустое состояние
   `PANEL_NO_REJECTED`) во всех пяти языках, с обратным переводом на русский
   для каждой. Носителю для вычитки хватит одного этого файла, лезть в код
   не придётся. Файл создаётся на шаге 2 и дополняется на шаге 3.
2. **Бандл растёт примерно на 270 kB.** Демо офлайн с локального диска,
   цена приемлема, но записывается честно.
3. **Названия юрлиц остаются по-русски на всех языках.** Это не недоделка,
   а требование §4; на демо проговаривается словами.

## Координация

- `package.json` и `package-lock.json` правятся с разрешения владельца продукта,
  но владелец файлов — Full-stack 1. Занести три новые зависимости
  в `docs/questions-to-fullstack.md` отдельным пунктом.
- Контракт данных не меняется: слой перевода живёт целиком во фронте и
  не требует ничего от `packages/contracts`. Если бэк когда-нибудь начнёт
  отдавать многоязычные тексты, таблица `src/i18n/data/` удаляется, а селекторы
  остаются.
